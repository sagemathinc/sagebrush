# test_pcimc_quickwins2: recorded deviations from Sage 10.9
test_pcimc_quickwins2.out is SageMath 10.9's output (VM2, ~/sage-conda; oracle input 78b72d6b…, output dc593d9f…), verbatim. Two choices were made in writing the statements, so that every line is Sage's:
- `nullity()`, `right_nullity()`, `left_nullity()` and `len(K)` (S03, S04, S13-S16, S31) are printed by value only (showr). Sage returns a Python `int` there, whose parent Sage prints as `<class 'int'>`. In Sagebrush, Sage's integers are Python ints with Integer's methods, so the same value's parent prints as Integer Ring. The values agree. This is the tracked int/Integer follow-up already recorded for test_pcimc_quickwins (S03, ...).
- The raw set reprs `{Z5(x) for x in Z5.unit_group()}` and `{Z24(x) for x in Z24.unit_group()}` (the book's own cells, 04-Modular_Arithmetic:852 and :858) are not compared; their sorted forms (S36, S40) are. Sagebrush's Python runtime keeps a set in insertion order, while CPython orders it by hash, so the printed order of the same set differs (`{1, 2, 4, 3}` vs `{1, 2, 3, 4}`). The elements agree. This is a runtime difference, not this PR's.
