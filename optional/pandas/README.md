# @sagebrush/pandas

Sagebrush's pandas 0.x (plan-pandas r7, M1): a subset of pandas 3.1.0's API, in Python over Sagebrush's numpy, as an optional package.

## The subset (M1)

- **Data:** `Series`, `DataFrame` and `Index`/`RangeIndex`, with the dtypes int64, float64, bool, str (pandas 3's default string dtype) and object, and the smaller integers astype gives.
- **Indexing:** `[]`, `.loc` and `.iloc`, with Copy-on-Write ownership. A derived object never shares a column with its source or with a caller's array.
- **Reading CSV:** `read_csv`, with sep, header, names, index_col, usecols, na_values, keep_default_na, dtype, nrows, skiprows, quotechar and parse_dates (False only).
- **Reading Excel:** `read_excel` for .xlsx and .xlsm workbooks (a formula's cached value, never evaluated; the 1900 and 1904 date systems), with skiprows, header, nrows, usecols and index_col. `.xls`, encrypted workbooks, `dtype=`, `converters=`, `parse_dates=` and a callable `usecols` raise NotImplementedError.
- **Missing values:** `isna`, `notna`, `isnull`, `notnull`.
- **Display:** text and HTML reprs, and six display options.
- **Reductions:** sum, mean, min, max and count.
- **Sorting and reshaping (for scikit-learn's lessons):** `sort_values` (by one or more columns, ascending per key, na_position, ignore_index; always stable: pandas' default quicksort isn't, so for tied keys its order is unspecified and this one is a valid answer), `unique`, `apply` (a function of each value, column or row), `fillna` (a value, or a dict per column), `astype` (between the subset's dtypes, a dict per column, and to int8, int16, int32, uint8, uint16 and uint32, which wrap as numpy's astype does), `rename`, `reset_index`.
- **Counting, joining and reshaping:** `Series.value_counts` (normalize, sort, ascending, dropna; ties in order of first appearance), `pd.concat` of Series and frames (rows or columns, outer or inner join, ignore_index, sort, verify_integrity; pandas' dtype rules for missing cells), `drop` (rows or columns by label), `melt` and `pd.melt`, `info` and `memory_usage` (deep only for numeric data: the sizes of Python objects are CPython's), and `to_numpy(dtype=, na_value=)`. Keys and dicts in `concat`, `bins` in `value_counts` and `level=` need a MultiIndex or an IntervalIndex and are refused.
- **float32 columns:** from float32 arrays, `dtype="float32"`, numpy float32 values or `astype`; they stay float32 through setting, sorting, filling, `concat` (numpy's promotion: float32 with int16 is float32, with int32 or int64 float64) and `diff`, reduce in float32 as pandas' nanops do (`sum`, `mean`, `min` and `max` are `np.float32`), and print, `describe` and `corr` as pandas does. `read_csv(dtype="float32")` is refused for now.
- **groupby:** by one key (a column, a Series or list of the same length, or the index), with `sort`, `dropna` and `as_index`; `size`, `count`, `sum`, `mean`, `min`, `max`, `std`, `var` (ddof, a float truncated toward 0 as pandas' C integer takes it; skipna), `median` and `agg` (a name, numpy's sum/mean/min/max, a function of each group, a list for one column, a dict, or named aggregation); iteration and `get_group`. Sums and means follow pandas' own two paths: numpy's per-run sum when the rows already come in group order without missing floats, else its Kahan summation. `std` and `var` are pandas' Welford update and `median` its middle value (or the mean of the two middle ones); a float32 column's `var` runs in float32, its `std` and `median` in float64, coming back float32 only when every value of the frame's float32 columns fits within 5e-4 (absolute; pandas decides per internal block; known.json lists the one case where that differs). Several keys, and lists of functions over a frame, need a MultiIndex and are refused.
- **Selecting and testing:** `take` (rows or columns by position), `any` and `all` (per Series, or per column of a frame), and an Index's `to_numpy`, `numpy.asarray` and `astype`. `Index.to_numpy` exports string labels as a `'<U'` array (as a str column does); `numpy.asarray` of a str Index is refused.
- **Series arithmetic:** `+ - * / // % **` with a number (a 0-d array too), a list, tuple, range or array (a tuple or range with pandas' deprecation warning), or another Series (aligned on the sorted union of their labels), their reflections, unary `-`, `+` and `abs`, and the named methods (`add`, `sub`, `mul`, `truediv`, `floordiv`, `mod`, `pow` and their `r` forms) with `fill_value` (filling either side where only it is missing; with a missing scalar, the scalar). NumPy 2's dtype rules apply, with a Python or numpy number as a weak scalar (a float32 column stays float32); division by zero is pandas' (`/` numpy's signed infinities; `//` and `divmod` by the signs of the dividend and of the zero, as float64; `%` NaN); bools and str values follow pandas. The named methods check a list, tuple or array's length ("Lengths must be equal") and, with one of those or a Series, skip pandas' zero-division masks, as pandas does; a range or an Index takes the operators' path. Object columns are refused for now.
- **The category dtype:** `astype("category")` (of a Series, or per column of a frame), `astype(pd.CategoricalDtype(categories, ordered=))`, `pd.Categorical(values, categories=, ordered=)`, `Series(..., dtype="category")`; a `Categorical` as a frame column (`pd.DataFrame({"c": cat})`, `df["c"] = cat`); the categories are the distinct values present, sorted (numbers before strings when mixed), or the ones given (a value outside them is missing); codes in the smallest signed integer type that fits (int8 for fewer than 127 categories). `.cat.categories`, `.cat.codes`, `.cat.ordered`; printing as pandas prints it (a Series' or `Categorical`'s categories line, at most 8 categories shown); selection (`head`, `iloc`, `loc`, masks, `dropna`) keeping the dtype; `isna`, `==` and `!=` (a scalar looked up among the categories by value and type; two categories only with the same categories, as a set when unordered, and the same `ordered`, else pandas' TypeError); `astype` back; `tolist`; `unique` (a `Categorical`); `count`. As in pandas, arithmetic, unary operators, `sum`, `mean`, `any`, `all` and order comparisons of an unordered category raise TypeError, as do `min` and `max` unless it is ordered. Everything else on a category column (sorting, `value_counts`, `groupby` and `set_index` by one, `fillna`, `info`, `describe`, `to_numpy`, the `.cat` methods that change categories, a float32, smaller-integer or datetime column as a category; a `Categorical` as a key, an index or columns, as the values set into a Series, or compared with a Series) raises NotImplementedError: a category column's codes are never read as values.
- **One-hot encoding:** `pd.get_dummies` of a Series, a list or a frame: one indicator column per category (the distinct values present, sorted, or a category column's own categories, unused ones too), named by the value or `prefix` + `prefix_sep` + value; `dummy_na`, `drop_first`, and `dtype` bool (the default), int or float. A frame encodes its str, object and category columns, or `columns`, after its other columns; `prefix` can be a string, a list or a dict. `sparse=True` and other dtypes are refused.
- **Comparisons:** `== != < <= > >=` and the named `eq`, `ne`, `lt`, `le`, `gt`, `ge` on a Series or a frame, with a number (or a 0-d array), a string, a time, a list-like, a 2-D array (frames), another Series or another frame; always a bool result, a missing value comparing False (True for `!=`). The operators need the same labels (a frame: rows and columns; a Series row for a frame: exactly its columns) and a list-like of the right length, with pandas' messages; the named comparisons align on the sorted union of the labels, a label one side lacks comparing False (True for `ne`), with `axis` on a frame and `fill_value` on a Series. Datetime columns compare with times, parsed strings (one by one in a list or Series) and NaT; a tuple or a range goes to the column's own array comparison as in pandas (numpy's broadcasting of one value for numbers, equal lengths for str and datetime columns); a Python number compares as a weak scalar (a float32 column against `0.1` at float32), a numpy number or a 0-d array as a strong one (at float64 for a float64 one); ordering times against None or NaN raises pandas' error, against NaT gives False; ordering numbers against a string, or a time against a number, raises pandas' error. Repeated column labels where labels are matched, a Series of repeated labels in a frame's named comparison, and `level=`, are refused.
- **DataFrame arithmetic:** the same operators, `divmod`, unary `-`, `+`, `abs` and the named methods (with `axis` and `fill_value`), column by column with the Series rules, pandas' zero-division masks in every case. The other operand can be a number or a 0-d array (a weak scalar), a list, tuple, range, Index or 1-D array (a row for the columns, or with `axis="index"` a column for the rows: an array of its own dtype, not a weak scalar), a 2-D array of the frame's shape or (rows, 1) or (1, columns), a Series (the columns' labels, or with `axis="index"` the rows'), or a frame with the same columns (rows aligned on the sorted union). Two frames with different columns, and a Series with other labels, are refused: pandas gives the added all-missing columns a dtype from its internal blocks. Repeated column labels where labels are matched, and `level=` (a MultiIndex), are refused too.
- **Summary statistics:** `describe` of a Series or a frame (percentiles, include, exclude; count, mean, std with ddof=1, min, numpy's linear percentiles and max for numbers, count, unique, top and freq for the rest) and `corr` (Pearson's, pairwise over the rows where both columns are finite, min_periods, numeric_only, or a function; `Series.corr`). These follow pandas' own steps (its nanops sums and its nancorr updates), so the floats are pandas'. Datetime columns and the rank correlations (spearman, kendall) are refused.
- **Exporting str data:** `to_numpy()` and `.values` of a str column or of a frame of only str columns, and `unique()` of a str Series, give a `'<U'` numpy array where pandas gives an object array (or its StringArray): Sagebrush's numpy has no object dtype yet. Missing values in str data, a frame mixing str with other columns, and `numpy.asarray` of str data are refused. `tests/test_str_export.py` states what Sagebrush gives.
- **Times:** naive `datetime64[us]` columns and `DatetimeIndex`, `Timestamp`, `NaT` and `to_datetime` (ISO dates and times, M/D/YYYY, YYYYMMDD, a `format` of `%Y %m %d %H %M %S %y %f`, numbers with a `unit` and `origin`; a list's format inferred from its first string, as pandas 3.1). Also `.dt.year/.month/.day/.hour/.minute/.second/.strftime`, an index's `.year/.month/.day/.strftime`, `Series/DataFrame.diff(periods)`, `dropna(how, thresh, subset, inplace)`, and `DataFrame.set_index(label)`. Sagebrush's numpy has no `datetime64` yet, so a datetime column is int64 microseconds inside the package: its `.values`/`.to_numpy()` raise NotImplementedError rather than give another type, as do `Timedelta`, timezones, nanosecond results, and times outside the years 1685–2255 (where those microseconds stop being exact).

Everything outside the subset raises `NotImplementedError("... is not in Sagebrush's pandas 0.x subset")` before doing any work. A pandas name outside the subset on an object (a Series, DataFrame, Index, groupby or `.dt`: `s.divmod`, `df.pivot_table`) raises one that is also an `AttributeError`, so `hasattr` gives False and `getattr` with a default gives the default (`tests/test_name_errors.py`). A name of the `pandas` module itself (`pd.pivot_table`) raises the builtin `NotImplementedError` only, because `from pandas import pivot_table` would turn an `AttributeError` into a bare `ImportError` without the message. `tests/test_unsupported.py` lists each such form, and `known.json` gives the reason for each one. `known.json`'s `value_divergences` also name the few ruled places where a value differs from pandas without a refusal (both about a frame with a float column added after construction: a groupby sum or mean can take a different summation path, and a float32 column's groupby std or median can come back in a different dtype; `tests/test_groupby_blocks.py` pins both).

## Limits

When the engine's limit `pandas.decoded_bytes` is finite (grading sets it; it is unlimited by default), `read_csv` preflights every allocation against that budget. It refuses with a `ValueError` before the growth. `tests/test_budget.py` and `tests/test_budget_map.py` check its six adversarial shapes, and `tests/test_budget_order.py` checks that each charge comes before the growth it admits (at zero headroom nothing is read or copied first).

## Tests

`tests/test_*.py` run under the built CLI with the package set (`node scripts/optional-packages.mjs test --pkgset ...`). Each is compared with its `.out`:

- **pandas' own output** (`tests/oracle/`, recorded by `tests/gen-oracle.sh` in the environment `tests/oracle-env.txt`) for every other test;
- **Sagebrush's output** for the tests listed in `tests/sagebrush-only.txt`, where the oracle can't speak: `test_unsupported`, `test_repr_escape`, `test_budget`, `test_budget_map`, `test_budget_order`, `test_read_excel_budget`, `test_read_excel_limits`, `test_str_export`, `test_groupby_blocks` and `test_known` (which checks `known.json`, and that every test is either in that list or has an oracle output, never both). `tests/gen-oracle.sh` skips that list.

A test with a `test_<name>.limits.json` beside it runs under those limits.
