# test_combinat: recorded deviations from Sage 10.9
Checked against real Sage 10.9 on Nov 1 (the VM2 oracle, wrapped variant; /scratch/sage2-notes/kernel/oracle, COMPARE.txt 24577be7). Lines 1-48 and 60-62 of test_combinat.out are Sage's output. Lines 57-59 are sagebrush-only structural checks (spied helpers), which the oracle skipped. Grader ruled these lines (04f715e1); @sagebrush approved 50 and 52-54 as (b), and 56 and 63 as (b) with the reasons below (sage-oracle-b-approvals.md).
- Line 50, `Permutation([1.5, 2])`: Sage accepts it and prints `[1.50000000000000, 2]`. Ours raises ValueError, because a permutation of {1, ..., n} has integer entries; truncating or keeping 1.5 makes a value that isn't a permutation (astra3's R2: refuse rather than silently change meaning).
- Line 52, `Compositions(-1)`: Sage constructs it ("Compositions of -1"). Ours raises ValueError, because a negative integer has no compositions, and R2 asks that each parent's domain be validated at construction.
- Line 53, `Partitions(-1)`: Sage constructs "Partitions of the integer -1". Ours raises ValueError, for the same reason.
- Line 54, `Permutations(-1)`: Sage constructs "Standard permutations of -1". Ours raises ValueError, for the same reason.
- Line 56, `stirling_number2(0, -1)` (part of the line): Sage raises OverflowError ("can't convert negative value to unsigned long", its C conversion). Ours returns 0, which is the combinatorial value: S(n, k) = 0 for k < 0. Sage's error comes from its implementation, not from a domain rule. The first oracle ran line 56 as one statement, which raised before printing. @sagebrush then ruled that its other parts need Sage equality, one statement per line. Probe 4 (VM2, Nov 1 14:33Z; input /scratch/sage2-notes/kernel/oracle/in4 ab60a6d1, output out4, oracle.out a59196c9) shows that Partition([2, 1]) == [2.9, 1] (False), Compositions(0).list() ([[]]), Compositions(0).cardinality() (1), Subsets(4, 5).cardinality() (0) and Subsets(4, 5).list() ([]) equal Sage's output. Only stirling_number2(0, -1) differs.
- Line 63, unhashable elements (`Combinations([[1], [1], [2]], 2)` and `Permutations([[1], [1], [2]])`): Sage raises TypeError (it hashes the elements). Ours groups them by equality and returns [[[1], [1]], [[1], [2]]], 2 and 3, because astra3's R1 required multiset grouping by equality, unhashable values included.
