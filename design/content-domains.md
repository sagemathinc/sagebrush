# Content-host configuration

William chose a fresh Sagebrush-only production `.com` / staging `.dev` content pair plus a submission to the PRIVATE section of the Public Suffix List (November 7, 2026). William confirmed ownership of `sagebrushusercontent.com` and `sagebrushusercontent.dev` on November 7. Only William changes DNS, submits to the PSL or deploys.

`web/content-domains.mts` is the configuration source. Production uses `sagebrushusercontent.com`; staging uses `sagebrushusercontent.dev`. Each files origin is exactly `https://files.<root>`. The files Worker keeps each environment’s legacy hostname alongside its new files hostname. The DEV API’s `FILES_ORIGIN` binding selects the new staging files origin when deployed. Production sharing stays disabled. No hosted runner or renderer is enabled.

This is a configuration change awaiting William’s deployment, not evidence that either new host is live. Deploy the DEV files Worker and verify the new host before deploying the DEV site that issues new URLs. The files Worker derives its hostname list from the same value that supplies the site’s `FILES_ORIGIN`. Its legacy hostname remains alongside the new one for old raw links. No path, query, signature, bucket, database or key changes here. Keep the legacy routes serving the same environment’s files with no redirect, path/query rewrite or key rotation. There is no automatic removal date: raw links and exported URLs require a separate reviewed retention decision before removing compatibility hosting. Production remains a separate deployment; this change does not enable its share or sync APIs.

Dynamic consumers already use the binding: collection responses in `web/share/server.ts` expose `files_origin`; shared viewers read that response; signed sync reads in `web/sync/server.ts` use `FILES_ORIGIN` for the no-store 303. Their authentication, signatures, paths and environment data stay unchanged. Local test origins remain injectable.

`runOrigin` and `renderOrigin` are reserved configuration, both empty. They do not supply runner frame URLs or output-shell URLs. Existing `web/output-shell/sites.mts` URLs remain empty, and its denial list includes legacy and configured content roots. The two-label site heuristic is deliberately not relaxed for a PRIVATE suffix. A later activation review must establish PSL adoption in supported browsers, actual role site boundaries, exact-host CSP/ancestors, cookie-free hosting and the existing real-host isolation gates. If PSL acceptance or rollout fails, keep the packaged variants and choose a separately reviewed domain layout.

The migration inventory originally found 17 references in 13 files before the output renderer landed. Those references now name this configuration or the `FILES_ORIGIN` binding. The two legacy root literals are centralized here to preserve current routes and existing output-shell rejections. Historical notes are not rewritten. Tests pin the legacy-host rejections against literal compatibility roots so the checks cannot become vacuous.
