# test_pcimc_quickwins: recorded deviations from Sage 10.9
test_pcimc_quickwins.out is SageMath 10.9's output (VM2, ~/sage-conda; oracle output 7a5911e1…) minus the lines of the statements below, which were dropped; every remaining line is Sage's, verbatim. Grader's review of #456 (9a2c98d6) asked for this file.
- S03, S08, S16, S49, S59: `type(...)` of an integer result (`xsrange`'s elements, `random_prime`, `prime_divisors`'s entries, `Primes()[0:3][0]`, the literal `41943`). Sage: `<class 'sage.rings.integer.Integer'>`. Ours: `<class 'int'>`. In Sagebrush, Sage's integers are Python ints, with Integer's methods (digits, bits, is_prime, ...) dispatched on them. The values and the methods agree; the type name does not. It is user-visible, so it is a TRACKED FOLLOW-UP (a sage-kernel item), not a choice made here.
- S21: `log(10^6, base=2)`. Sage prints `6*log(10)/log(2)` (Pynac takes the perfect power out of log(10^6)); ours prints `log(1000000)/log(2)`. The same value: the pcimc book's use of it, `2*floor(log(N, base=2))`, is S22 and equals Sage's (38). Follow-up: log of a perfect-power integer, simplified as Pynac does.
- S20: dropped as a malformed check of mine, not a deviation. It compared two independent `sample()` calls, so its result is random in Sage too. `sample`'s property (k distinct elements of the population) is checked in the docstring example instead.
